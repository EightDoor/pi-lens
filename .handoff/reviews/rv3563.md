Node 22's global `fetch` ignores `HTTPS_PROXY`. In this container `GH_TOKEN` is a 14-character placeholder, and the egress proxy swaps it for the real credential. A direct `fetch` sends the placeholder to GitHub and gets 401.

```

$ node -e 'fetch(".../user", {Bearer GH_TOKEN})'                            -> 401
$ NODE_USE_ENV_PROXY=1 node -e '...same...'                                 -> 200
$ node scripts/ci-verdict.mjs 3602
GitHub REST API error for repos/apmantza/pi-lens/pulls/3602                 -> exit 70
$ NODE_USE_ENV_PROXY=1 node scripts/ci-verdict.mjs 3602
...full 26-row table... Merge state: MERGEABLE / Transport: rest /
gating check(s) still queued or in progress: Unit tests                     -> exit 3
```

- The issue says the script "cannot run there". After this change it still exits 70 there.
- The body calls the token "a real GH_TOKEN" and says the proof was "captured for real". The red transcript uses `GH_TOKEN=faketoken123`, and the body has no post-fix live run. That run would have shown this failure.
