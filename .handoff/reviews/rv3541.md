## Spec-compliance findings (issue acceptance)

### F1 (Medium, behaviour): the actionable fix still erases part of a concurrent agent edit

Code involved:
- `clients/actionable-warnings.ts:2083-2109`: reads `content`, calls `openFile` and then `codeAction`, all outside any queue.
- `clients/actionable-warnings.ts:2110`: `applyWorkspaceEdit(edit, cwd, {mutationContext})`. It passes no `documentVersions` and no expected content.

Inside the queue, `preflightWorkspaceEdit` (`clients/lsp/edits.ts:1183`) checks a text op only when `op.version` is set and `documentVersions` is passed. An unversioned `changes` edit is applied at the server's positions to whatever bytes are on disk at that moment.

**Probe.** This was a throwaway copy of `lsp-writers-mutation-queue.test.ts`'s harness, since deleted. The `codeAction` double is gated. While it is parked, the agent prepends a line through pi's real `withFileMutationQueue`. The gate then opens.

```
PROBE applied=1 disk="constt const AGENT = 2;\nvalue = 1;\n"
× the actionable fix does not rewrite the agent's line at the code action's stale position
AssertionError: expected false to be true
```

The result:
- The agent's `export const AGENT = 2;` becomes `constt const AGENT = 2;`.
- The intended target line (`value = 1;`) is left unfixed.
- The summary still reports `applied=1`.

This is the #3541 defect class ("can erase a concurrent agent edit"). It happens on the default agent_settled path, the same next-run concurrency that `InstallHold` relies on. It is pre-existing, not a regression. But the PR closes #3541, and the body's Named-residuals row misdescribes it:

> the actionable fix reads the file and asks the server for a code action before it enters the queue | accepted: an agent edit in that window makes the edit stale (applied at the server's positions), not an erasure, and the queued preflight rechecks the edit's preconditions

**Remedy (rung: no new abstraction; reuse the preflight).**
1. The fix already holds `content` at `:2084`. Pass it to `applyWorkspaceEdit` as a per-path expected content.
2. In `preflightWorkspaceEdit`'s `contentFor`, which now runs inside the queue, compare the disk bytes to it.
3. On a mismatch, skip. Record the skip as a `stale_content` reason, or throw the existing preflight error.
4. Add a red-first case shaped like the probe above.

If the fixer prefers not to fix it here, the body must reclassify the row as an erasure and link a tracking issue, and the title should say `refs #3541` rather than `closes`.

**Class sweep.** This is shape only; it has not been verified across callers.
- `tools/lsp-navigation.ts:1490-1504` has the same shape. `rename` is computed from the server's view, which `openFileBestEffort` synced earlier. It is then applied without a content precondition.
- The server-initiated `workspace/applyEdit` handler passes `documentVersions`. Versioned edits are covered there; unversioned ones are not.

## Standards-compliance findings (AGENTS.md / PR contract)

### F2 (Low, contract): the Observability answer names only the failure-path record

The body names `host-file-mutation-queue-unavailable`. That record fires only when the queue cannot be reached.

The PR adds new blocking waits:
